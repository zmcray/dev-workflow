# Autonomous runs

For `/goal`, `/factory`, or any hands-off run across issues.

## Autonomous runs (goal mode)

A fourth axis: does the run pause for the human? Default is interactive (confirm between pre-work steps). In **goal mode** the human sets an objective spanning one or more issues and the agent runs to completion without prompting: every would-be question becomes a stated one-line judgment call, logged to the relevant Linear issue so decisions stay auditable. Planning, flow/effort decisions, and architecture calls stay in the main thread; execution subtasks are delegated per `delegation.md`. Goal runs work issues strictly sequentially under the merge-on-green rule and end only when the objective is met or a hard stop fires: an unmergeable PR, a red baseline at run start, the kick-back rule, or anything destructive the plan doesn't cover. A chunk still red after its retry is not a stop: mark it `failed` with a one-line Linear comment and move on, skipping chunks that depend on it or share its files. On Claude Code this is the built-in `/goal <objective>` command, which keeps the session working until the objective is met, and `/factory`, which runs `/goal` over the whole `spec-ready` queue with a budget (see `~/Developer/software-factory/DISPATCH.md` > Night budget); build each issue with Compound Engineering `/lfg` and apply the AGENTS.md core and `build.md` rules between issues (merge on green, Linear sync, session close). On other harnesses, apply this contract natively when the user asks for a hands-off run.

**Every goal run, in this order:** (1) **Chunk sweep**... find plans in `docs/plans/` that belong to the objective's issues and have no `## Chunks` section; any with 3+ Implementation Units or a unit over the chunk bar gets cut into chunks first (`/packets`). (2) **Pull** only unblocked `spec-ready` issues that carry neither `gate:human` nor `ops`, highest priority first; skip any `design:screens`, `design:journey`, or `design:product` issue that has no canvas link (`design.md` > Spec gate), even when it is `spec-ready`, and report it as `no-canvas`; for a parent issue, work its chunks in `blocked by` order. An empty queue ends the run with "plan first"... never improvise work. (3) **Per landing group:** build the group's chunks in order on one branch (`chunks.md` > Landing: group PRs); a chunk that lands alone is its own group. If a chunk carries a build packet pointing at a plan unit, do not re-plan; execute that unit, stay inside its file scope, commit it, and pick the model for delegated work from its `tier:*` label. (4) **Human gate discovered mid-build:** if a step turns out to need a person (the packet missed it), do not wait, guess, or fake the check. Push the branch, open a draft PR, add `gate:human`, post a one-line Linear comment saying exactly what the human must do (a procedure also gets its wizard, per `chunks.md` > Wizards for human procedures), and move to the next unblocked issue. This is a **park**, not a hard stop: chunks whose file scope overlaps the parked one are skipped too. (5) **Endings:** queue empty and budget stop (credit or plan headroom ran out) are both normal... report which, leave the rest `spec-ready`, and list every parked `gate:human` issue in the run report so the morning batch is one list.

**Red default branch mid-run.** When the default branch's full suite goes red after the run has merged something, the run does not stop. It reverts the breaking merge and keeps going:
- **Infrastructure first.** A failure with only runner, simulator or infra errors (launch failures, `Busy`, timeouts with no assertion failure) gets one re-run. Still red the same way: hard stop and file an infra Bug, no revert.
- **One suspect.** Look at the merges since the last green full-suite run. Exactly one, and it is the run's own: that is the suspect. Several: run the suite on the commit before the newest, at most 2 steps. Still ambiguous, or not the run's own: hard stop.
- **Revert through a PR**, never a direct push, merged on green like any other PR. File a Bug with the failing tests, the run link and the revert PR; reopen the original issue, blocked by that Bug. Its ledger row becomes `reverted`.
- **Cap.** A second revert in one run is a hard stop once it merges: two breaks in a night means something systemic.

`/factory` > Red main has the procedure.
